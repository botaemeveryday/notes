# Контрибьютинг

Структура файлов, front matter, проверки и процесс Pull Request.

## С чего начать

| Что хотите сделать | Куда идти |
|---|---|
| Нашли ошибку, править не готовы | [Issue](https://github.com/botaemeveryday/notes/issues/new?template=content-error.md) |
| Поправить текст лекции | `content/posts/<курс>/<лекция>/index.md` → PR |
| Добавить лекцию | новая папка в существующем курсе |
| Добавить курс | новая папка в `content/posts/` с `_index.md` |
| Свои конспекты по курсу, который уже есть | отдельная папка + общий `subject`, см. [ниже](#несколько-конспектов-по-одному-предмету) |

Последний случай — самый частый и самый важный. **Не смешивайте записи разных преподавателей, авторов или годов в одной папке.** Одна папка — один вариант конспекта.

## Локальная сборка

Требования: Hugo **extended ≥ 0.132** (формулы считаются на сборке, раньше не заработает), Node.js, npm, Python 3.11+, Git.

```bash
git clone https://github.com/botaemeveryday/notes.git
cd notes

npm install        # Tailwind и зависимости
npm run build      # сборка стилей
hugo server -D     # http://localhost:1313
```

Шрифты, KaTeX и иконки лежат в репозитории — качать ничего не нужно.

`npm run build` перезапускайте после появления новых Tailwind-классов, иначе они не попадут в CSS. **Если правку видно в разметке, но не видно на странице — начинайте отсюда.**

Перед отправкой PR:

```bash
pip install pyyaml
python scripts/check-content.py            # то же, что проверит CI
python scripts/check-content.py --strict   # ещё и предупреждения
```

| Объект | Соглашение | Примеры |
|---|---|---|
| Папка курса | `kebab-case` | `databases`, `operation-systems` |
| Папка варианта | `<предмет>-<фамилия>` | `java-makarevich`, `java-butenko` |
| Папка варианта с автором | `<предмет>-<фамилия>-<автор>` | `java-makarevich-notakeith` |
| Папка лекции | `kebab-case` | `lecture-01` |
| Изображения | осмысленное имя | `cover.png`, `process-tree.png` |

Внутри одного курса держитесь единого стиля нумерации лекций — либо `lecture-01`, либо тематического `allocator-02-26`. Не смешивайте.

```
content/posts/<курс>/<лекция>/
├── index.md
└── images/
    └── process-tree.png
```

## Front matter лекции

```yaml
---
title: "Название лекции"
description: "Короткое описание, 1–2 предложения"
date: 2026-05-07
weight: 3                    # номер лекции
tags:
  - Базы данных
  - 4 семестр

authors: []                  # если автор лекции отличается от автора курса
noteType: human              # human | ai | ai-pro
aiModel: ""
aiSource: ""
---
```

Обязателен `title` и **либо** `date`, **либо** `weight` — иначе проверка PR не пройдёт.

`weight` задаёт номер лекции на обложке. Без него номер считается по позиции в списке: для сплошного курса это нормально, но ломается, когда лекции добавляют не по порядку.

`draft: true` скрывает страницу. В PR его лучше не оставлять.

### Метка происхождения

| `noteType` | Метка | Когда ставить |
|---|---|---|
| `human` | Авторский (зелёная) | Написан человеком. Если ИИ помогал с оформлением — метка та же, но заполните `aiModel`, это честнее |
| `ai` | Нейроконспект (янтарная) | Сгенерирован моделью по аудио или презентации |
| `ai-pro` | Нейроконспект (фиолетовая) | То же, но моделью повышенной точности |

Для `ai` и `ai-pro` заполняйте `aiModel` и `aiSource` — иначе читатель не поймёт, чему доверяет. Оба попадают в подсказку при наведении на метку.

`noteType` наследуется: если у лекции его нет, берётся из `_index.md` курса.

## Front matter курса (`_index.md`)

```yaml
---
title: "Базы данных"
description: "Реляционная модель, нормализация, индексы, транзакции."
semester: 4
accent: 3                    # 1..6 — цвет курса
weight: 10                   # порядок в списке и порядок вариантов

teacher: "Мацнев Николай Игоревич"
author: "notakeith"          # или authors: [...]
academicYear: 2025           # → «2025/26»

subject: "databases"         # только если вариантов несколько
noteType: human              # метка по умолчанию для всех лекций курса
abbr: ""                     # аббревиатура на карточке, иначе по инициалам
tag: ""                      # маленькая плашка на карточке
---
```

`accent` — **единственный источник цвета**. Он красит карточку на главной, шапку курса, обложки всех лекций и сайдбары. Точечно переопределить можно у лекции через `cover_color` и `cover_color_soft`, но без нужды не стоит.

`author` понимает и ник GitHub (`notakeith` → аватарка и ссылка подтянутся сами), и обычное имя, и список:

```yaml
authors:
  - notakeith
  - name: "Пётр Петров"
    github: "petrov"
```

## Несколько конспектов по одному предмету

Одна папка — один вариант. Вариант определяется тремя вещами: **преподаватель, автор конспекта, учебный год**. Варианты склеиваются общим ключом `subject`:

```
content/posts/java-makarevich-notakeith/_index.md
    title: Java   subject: java   teacher: Макаревич Р. Д.   author: notakeith   academicYear: 2025   weight: 10

content/posts/java-makarevich-petrov/_index.md
    title: Java   subject: java   teacher: Макаревич Р. Д.   author: Петров К.   academicYear: 2025   weight: 20

content/posts/java-butenko-notakeith/_index.md
    title: Java   subject: java   teacher: Бутенко А. В.   author: notakeith   academicYear: 2024   weight: 30
```

На главной это **одна** карточка «Java». Она раскрывается списком вариантов: преподаватель, метка происхождения, автор, число лекций, учебный год. Внутри курса кнопка открывает выбор, выбор запоминается в браузере — следующий клик по предмету на главной откроет его же.

Требования:

- у всех вариантов одного `subject` совпадают `title`, `accent`, `semester`;
- у каждого варианта заполнены `teacher` и `author`;
- `weight` задаёт порядок вариантов. Без него порядок определяется фамилией и годом — предсказуемо, но не факт что так, как вам хочется.

Заголовок предмета берётся из варианта с наименьшим `weight`. Если папки называются по-разному, а показать надо одно название — поставьте `subjectTitle` любому из вариантов.

### Учебный год

```yaml
academicYear: 2025        # → 2025/26
academicYear: "2025/26"   # так тоже можно
```

Год виден плашкой рядом с преподавателем. Если у **того же самого** преподавателя есть конспект за более свежий год, старый помечается приглушённой плашкой, а на его странице появляется баннер со ссылкой на новый. Сравнение идёт строго внутри преподавателя — разные лекторы с разными годами друг друга не «устаревают».

Год необязателен, но без него эта механика не работает.

## Формулы

Синтаксис LaTeX, считаются **на сборке** через KaTeX. На клиенте JS для формул больше не грузится.

```
$inline$    \(inline\)
$$display$$ \[display\]
```

Блок ` ```math ` — то же самое display-формулой.

**Ловушка с долларом.** Одиночный `$` — инлайновый разделитель, поэтому пара обычных долларов в одном абзаце превратится в формулу и покрасится в красный:

```
цена 5$ и 10$        ← сломается
цена 5\$ и 10\$      ← правильно
```

Ошибка в формуле не роняет сборку — KaTeX красит её красным прямо на странице. Проверяйте локально.

## Иконки

Иконки вставляются в разметку на сборке, никакого JS. В тексте лекции:

```
{{< icon "download-outline" >}}
{{< icon name="warning-outline" class="text-warning" >}}
```

Имена — из [ionicons](https://ionic.io/ionicons). **Если нужной иконки ещё нет в `assets/icons/`**, сборка выведет предупреждение, а на её месте будет пусто. Добавить:

```bash
./scripts/vendor-assets.sh
```

Скрипт сам находит имена в шаблонах и контенте. Если имя вычисляется в шаблоне или приходит из front matter — впишите его в массив `EXTRA` внутри скрипта, грепом такое не находится.

## Pull Request

```bash
git checkout -b fix/cpp-exceptions
# правки, проверка локально
```

Заголовок PR — [Conventional Commits](https://www.conventionalcommits.org/ru/v1.0.0/):

```
<type>(<scope>): описание
```

| Тип | Когда |
|---|---|
| `feat` | Новая лекция, курс или функциональность сайта |
| `fix` | Исправление ошибки, опечатки, битой ссылки |
| `docs` | README, CONTRIBUTING и прочая документация |
| `style` | Оформление без изменения смысла |
| `refactor` | Реорганизация без изменения смысла |
| `chore` | Зависимости, конфиги, CI, скрипты |
| `perf` | Оптимизации |

**Scope** — курс (`cpp`, `databases`, `java`) или компонент сайта (`layouts`, `shortcodes`, `ci`). Можно опустить.

```
feat(cpp): add lecture concepts
fix(os): typo in lecture-03
chore: update hugo to 0.148
```

Ломающие изменения помечайте `!`: `refactor(layouts)!: split teachers into separate folders`.

### Что проверит CI

| Проверка | Блокирует |
|---|---|
| `scripts/check-content.py` — front matter и структура | да |
| `npm run build` + `hugo --gc --minify --printPathWarnings` | да |
| Внутренние ссылки и якоря | да |
| Внешние ссылки | нет, только отчёт |
| Заголовок PR по Conventional Commits | да |

Собранный сайт кладётся в артефакты прогона — можно скачать и посмотреть, не поднимая Hugo локально.

## Авторство

Контрибьюторы собираются автоматически из истории git и показываются в футере. Отдельно вписывать себя никуда не нужно — достаточно коммита от вашего аккаунта.

Если вы автор или соавтор конспекта (крупные правки или обновление от 30% текста) — добавьте себя в `authors` во front matter лекции.
